`buildSession()` creates one session inside a program, saves its blocks and exercises, and can
optionally publish it. The safer workflow is draft first, inspect second, publish last.

<Steps>
  <Step title="Resolve every exercise">
    Use the [exercise library](/developers/sdk/exercises) to turn names into TrainHeroic ids.
  </Step>
  <Step title="Build a draft">Set `publish: false` and keep the returned `pwId`.</Step>
  <Step title="Read it back">Verify the encoded session before it becomes athlete-visible.</Step>
  <Step title="Publish deliberately">
    Call `publishSession()` only after the draft matches the intended programming.
  </Step>
</Steps>

```ts lineNumbers expandable {30}
import { buildSession } from "@trainheroic-unofficial/js";

const { match } = await library.resolve("Back Squat");
if (!match) throw new Error("Choose one exercise before building");
if (match.units[0] !== "reps" || match.units[1] !== "lb") {
  throw new Error("Choose an exercise with reps and pounds as its fixed units");
}

const { pwId, workoutId } = await buildSession(client, {
  programId: 12345,
  index: library,
  date: [2026, 8, 17], // [year, month, day], with a 1-based month
  instruction: "Warm up first.",
  blocks: [
    {
      title: "Strength",
      exercises: [
        {
          id: match.id,
          sets: 5,
          reps: 5,
          primaryUnit: "reps",
          weight: 225,
          secondaryUnit: "lb",
          rpe: 8,
        },
      ],
    },
  ],
  publish: false,
});
```

`reps` and `weight` accept one scalar for every set or a per-set array such as
`reps: [5, 5, 3]`. State `primaryUnit` for the `reps` slot and `secondaryUnit` for the
`weight` slot. `buildSession` checks both against the exercise library before writing.

## Options

<TypeTable
  type={{
    programId: {
      type: "number",
      required: true,
      description:
        "The program that receives the session. Use a team's program or a roster athlete's calendar; a personal calendar rejects coach writes.",
    },
    index: {
      type: "ExerciseIndex",
      required: true,
      description:
        "The exercise library. Every exercise and its units are checked against it before the first write.",
    },
    blocks: {
      type: "BlockSpec[]",
      required: true,
      description: "The session's blocks, each with a title and its exercises.",
    },
    date: {
      type: "[year, month, day]",
      description:
        "The calendar day for the session, with a 1-based month. Required unless you pass timelineDay.",
    },
    timelineDay: {
      type: "number",
      description: "The day number in a fixed-length program. Use it in place of date.",
    },
    publish: {
      type: "boolean",
      default: "false",
      description: "Publish the session to athletes after it saves. Leave it off to build a draft.",
    },
    instruction: {
      type: "string",
      description: "The session's coach instructions, saved after the blocks.",
    },
    confirmSetSplit: {
      type: "boolean",
      default: "false",
      description: "Allow a prescription above ten sets to become consecutive blocks.",
    },
  }}
/>

## What it returns

<ResponseField name="pwId" type="number" required>
  The session's placement in the program. Read, publish, unpublish, copy, and remove operations
  use it.
</ResponseField>

<ResponseField name="workoutId" type="number" required>
  The underlying workout record.
</ResponseField>

<ResponseField name="advisories" type="{ notes: string[]; warnings: string[] }" required>
  Notes and warnings from the build, such as a set count that was split across blocks.
</ResponseField>

:::warning
Publishing makes the session visible to athletes. The MCP and CLI surfaces require explicit
confirmation for that step; direct SDK callers own their own confirmation policy.
:::
