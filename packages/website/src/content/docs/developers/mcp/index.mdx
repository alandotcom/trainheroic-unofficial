The hosted server is the simplest MCP deployment: one URL, OAuth login, and a tool set selected
from the role on your TrainHeroic account. To keep the server process and your credentials on
your own machine, run a [local stdio server](/developers/mcp/local) instead.

```text
{{mcp-url}}
```

## Add the server

<CodeGroup>

```console Claude Code
$ claude mcp add trainheroic --transport http {{mcp-url}}
```

```json Other MCP clients
{
  "mcpServers": {
    "trainheroic": {
      "url": "{{mcp-url}}"
    }
  }
}
```

</CodeGroup>

The client opens the TrainHeroic sign-in the first time the server needs authorization. The
server keeps your TrainHeroic credentials inside the encrypted OAuth grant and never forwards
the client's bearer token to TrainHeroic. The [privacy policy](/privacy) has the details.

## Role-aware tools

<Tabs>
  <Tab title="Coach">
    A coach account gets the coaching surface plus the account's own athlete-training tools.
  </Tab>
  <Tab title="Athlete">
    An athlete account gets profile, workouts, history, PR, working-max, leaderboard, and
    set-logging tools.
  </Tab>
</Tabs>

Two optional endpoints narrow the connection to one role:

| Endpoint                | Scope                       |
| ----------------------- | --------------------------- |
| `{{mcp-url}}/coach`     | Coaching tools only         |
| `{{mcp-url}}/athlete`   | Athlete-training tools only |

The coach-only endpoint exposes no tools when the signed-in account is athlete-only.

## Hosted-only features

The hosted server adds D1-backed history warehouses and a feedback tool. Ask the assistant to
report a problem and it can attach recent tool context for the maintainers.
