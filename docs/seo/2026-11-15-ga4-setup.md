## Collection boundary

Blume's native consent manager holds the local analytics bootstrap until the visitor accepts.
Decline leaves Google unloaded. Cookie settings in both footers reopen the choice; revoking
consent triggers a reload through Blume. The bootstrap also checks consent and the production
origin before loading Google. Preview hosts and local development send nothing.

The bootstrap sends static canonical URLs without query strings or fragments. The initial
referrer is reduced to its origin. Astro navigation updates the canonical page and avoids
duplicate page views. Google Signals and advertising personalization are disabled in the
tag configuration. Analytics cookies expire after 90 days, renewed by visits.
Google uses a separate `trainheroicAnalytics` queue, following Google's
[custom data layer instructions](https://developers.google.com/tag-platform/tag-manager/datalayer).
Blume's automatic search and feedback events therefore have no Google queue to forward to.

The `/export` app excludes the bootstrap, and a runtime guard also rejects that canonical
route. No form values, training data, real downloads, raw search terms, OAuth parameters, or
user identifiers are included. Built-in enhanced measurement is off. There are no Google
Ads links or new backend measurement endpoints.

## Event definitions

| Event | Meaning |
| --- | --- |
| `page_view` | A consented visit to a public page |
| `export_open` | Click on a link to the export app |
| `connector_setup_open` | Click on a link to `/connect` |
| `connector_endpoint_open` | Click on a hosted MCP endpoint link |
| `sample_csv_download` | Click on the synthetic sample CSV download |

Actions send a fixed event name and destination stream only, with the current public page
context. They do not prove completed exports, saved files, OAuth success, or successful MCP
tasks. Keep existing Sentry authorization and tool-outcome metrics separate. Do not label the
intent events as completed conversions.

## Validation and deployment

Run `pnpm --filter @trainheroic-unofficial/website test` for the privacy and navigation
regressions. Build the website and verify that the local bootstrap is inert `text/plain`
on public pages, absent from `/export`, and accompanied by consent controls. Run `pnpm check`
for the workspace checks.

Local validation passed: `pnpm check`, five analytics regression tests, production and
`ASTRO_BASE=/seo-check` builds, and metadata/link checks across 23 sitemap pages with 1,764
local links and anchors. A generated-HTML check confirmed inert analytics scripts and consent
controls on public pages, no eager Google tags, and no analytics bootstrap on `/export`.
These checks do not establish live GA4 ingestion.

After deployment, verify a consented public visit in GA4 Realtime and inspect the network
payloads. Confirm that declining produces no Google requests, Cookie settings can withdraw
consent, and actual export use produces no Google requests. Brave Shields or other blockers
may suppress analytics. Consent and blockers mean GA4 counts will not equal Search Console
clicks or total visitors.
